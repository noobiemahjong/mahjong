## 2. doc-gate 规则（G1–G12）

扫描范围：`-Root <目录>` 指定扫描根（默认仓库根）下的 `*.md`；排除 `.git/`、`content/`、`lib/`、`bin/`、`obj/`、`build/`、`tools/doc-gate/tests/fixtures/`。

G12 只警告不阻断；其余红即 exit 1（`-Fail` 模式）。

| 编号 | 判定 |
|---|---|
| G1 | 相对链接可解析；跳过 `http(s)`/`mailto:`/`#`；仓外链接只报告 |
| G2 | 文件首三字节不得为 `EF BB BF` |
| G3 | 不得出现 `CR` |
| G4 | 同一表块：分隔行后的每行单元格数 = 表头；行内无未转义双竖线（围栏代码块与行内代码内的竖线跳过） |
| G5 | 单行 ≤5000 字符 |
| G6 | 仅 `docs/milestones/README.md` 的表行 ≤300 字符 |
| G7 | 每篇 ≤ `doc-budgets.json` 的 `limitBytes`；`limits` 只接受精确路径（相对仓库根、`/` 分隔、区分大小写）；未登记文档只警告，新增文档同提交登记 |
| G8 | `limitBytes` ≤ `doc-budgets-baseline.txt` 对应值；上调 = 同提交改 baseline + Agent Note，门禁只校验两者一致，合理性由评审判定 |
| G9 | `tools/**/*.ps1` 与 `tools/git-hooks/*` 纯 ASCII |
| G10 | Note：路径 `.agents/notes/{lifecycle}/{class}/yyyy-mm-dd-slug.md`；lifecycle ∈ {proposed,implemented,rejected,archived}；class ∈ {feature,bug-fix,simplification,architecture,process,testing}；首行 `# Agent Note:`；`Status:` 与 lifecycle 一致；四段齐全；禁止 `INDEX.md`；豁免 `.agents/notes/README.md`、`.agents/notes/AGENTS.md`、`.agents/notes/000-template.md`，其余 `.md` 必须符合 Note 规则 |
| G11 | `docs/engineering/pitfalls/` 的 `000-template.md` 不计入编号；首篇 `001`，编号连续；README 不写编号区间 |
| G12 | 非表格/代码/列表的段落须为单物理行（只警告）；豁免元数据头块（`状态`/`依赖`/`对应 master`/`验收` 行）、引用块、缩进续行 |

`doc-budgets.json` 至少登记：根 `AGENTS.md`、`docs/AGENTS.md`、`docs/development.md`、`docs/architecture.md`、`docs/DESIGN.md`、`docs/TABLES.md`、每篇 milestone 与每篇 task、每篇 Note 的精确路径（不写通配）；上限取 [docs/AGENTS.md](../../AGENTS.md) 预算表。baseline 与 json 同步。

schema：根对象 `version`（整数）、`limits`（数组，元素 `{ "path": string, "limitBytes": integer }`）；`path` 精确且相对仓库根，不写通配、不写盘符、区分大小写；不含 `toleranceBytes`。

样例（节选，其余条目按上文覆盖范围登记）：

```json
{
  "version": 1,
  "limits": [
    { "path": "AGENTS.md", "limitBytes": 6144 },
    { "path": "docs/AGENTS.md", "limitBytes": 6144 },
    { "path": "docs/development.md", "limitBytes": 8192 },
    { "path": "docs/architecture.md", "limitBytes": 8192 },
    { "path": "docs/DESIGN.md", "limitBytes": 65536 },
    { "path": "docs/TABLES.md", "limitBytes": 16384 },
    { "path": "docs/milestones/M0.1/T-2-质量底座.md", "limitBytes": 10240 },
    { "path": "docs/subsystems/core.md", "limitBytes": 8192 },
    { "path": "docs/subsystems/flow.md", "limitBytes": 8192 },
    { "path": "docs/cookbook/build.md", "limitBytes": 8192 },
    { "path": "docs/cookbook/run.md", "limitBytes": 8192 },
    { "path": "docs/cookbook/aot-export.md", "limitBytes": 8192 }
  ]
}
```

后五条对应 T-6 新建文档，限值在此先行登记、同批写 baseline 行，文件由 T-6 建立；`doc-budgets-baseline.txt` 每行 `path\tlimitBytes`，G8 以 baseline 为棘轮基准、json 为当前值。

违规夹具：`tools/doc-gate/tests/fixtures/<case>/` 各建一例（坏链接、BOM、CRLF、超预算、错 Note、重复 pitfall 编号）；`tools/doc-gate/tests/run.ps1` 逐例跑 `doc-gate.ps1 -Root <fixture> -Fail`，断言退出 1，修复后断言退出 0；仓库根扫描排除该目录，夹具不参与仓库自检。「错 Note」夹具在 fixture 根内自建 `.agents/notes/{lifecycle}/{class}/` 结构与错位文件名。

## 3. commit-msg 钩子

- 路径：`tools/git-hooks/commit-msg`；安装：`git config core.hooksPath tools/git-hooks`。
- 规则：首行匹配 `^(feat|fix|docs|refactor|chore|test|perf|build|ci)(\(.+\))?: .{1,50}$`；正文非空行 ≤10；空行不计。违规 exit 1 并打印原因。
- 测试：`tools/git-hooks/tests/run.ps1` 在临时 git 仓库装钩子，好/坏 commit message 各 2 条，断言坏 exit 1、好 exit 0。

## 4. CI

`.github/workflows/ci.yml`：

- `on: push, pull_request`（不加 `paths:`）。
- `runs-on: windows-latest`；`actions/setup-dotnet` 固定 `10.0.401`。
- 步骤：restore → build → test → doc-gate（`pwsh -File tools/doc-gate/doc-gate.ps1 -Fail`）→ 钩子测试（`pwsh -File tools/git-hooks/tests/run.ps1`）。
- 设置 `git config core.hooksPath tools/git-hooks`（让钩子测试可跑）。
- 失败即红；不跳过测试。

## 5. 验收

1. 用 `-Root <fixture>` 逐类造违规 → 对应 G 红；修复 → 绿。
2. 钩子拒绝坏标题/超长 body；好消息通过（`run.ps1` 断言退出码）。
3. CI 判据：workflow 就绪 + 本地等价命令（`dotnet build`、`dotnet test`、doc-gate `-Fail`）全绿即满足；首次远程绿由用户 push 后回填，回填前任务表记「CI 待远程确认」。
4. doc-gate 自身纯 ASCII（G9），退出码稳定。

- `tools/doc-gate/README.md`：用法、退出码、规则清单、登记与排除约定、夹具与实现口径。
- `tools/doc-gate/tests/run.ps1` 与 `tests/fixtures/{bad-link,bom,crlf,over-budget,bad-note,pitfall-numbering}/{bad,good}`：每根自带最小注册表，bad 断言退出 1 且命中目标 G，good 断言退出 0。
- `tools/git-hooks/commit-msg`（sh、纯 ASCII/LF、标题正则、正文非空行 ≤10）、`tools/git-hooks/tests/run.ps1`（一次性 git 仓库 + `sh` 直连自检）、`tools/git-hooks/README.md`。
- `.github/workflows/ci.yml`：push/PR 无 `paths` 过滤；windows-latest、SDK 10.0.401、restore → build `-warnaserror` → test → `core.hooksPath` → doc-gate `-Fail` → 钩子测试。

验收对照（§5）：`-Root` 夹具逐类造违规 → 对应 G 红、good 根 → 绿；钩子拒绝超 50 字符标题、11 行正文与空消息；workflow 就绪且本地等价命令全绿，CI 待远程确认；门禁脚本自身过 G9、退出码稳定。

偏差：

- G9 口径收窄为 `tools/**/*.ps1` 加 `tools/git-hooks/` 无扩展名钩子：spec 字面 glob 会连中文 `README.md` 判红。
- G7 的未登记/文件不存在记 WARN；G2 的非法 UTF-8 记 WARN；BOM、CR 等记 ERROR。
- G11 只校验编号连续，pitfalls 与 README 的「编号区间」文字保留评审。
- G1 只查行内链接与图片，不查引用式/自动链接；仓外 WARN 不拦。
- 夹具 `<case>/{bad,good}` 双根，每根自带最小注册表；BOM/CRLF 存真实字节，靠 `.gitattributes` 的 `-text` 保真。
- 扫描排除额外加 `addons/`（vendor）与 `tools/doc-gate/tests/fixtures/`（夹具必须能红）。
- 钩子标题按字符数不按字节（中文 `20 字符/60 字节` 过），用 `od -An -v -tu1` 字节分类（`-tu1` 的 `*` 压缩会数错）；正文行先去 `CR`。
