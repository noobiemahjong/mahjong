# Agent Note: M0.3 任务页与变异台账预算上调

Status: implemented — `docs/milestones/M0.3/T-1-规则表与数值定稿.md`、`T-2-庄家计分.md` 由 10240B 上调到 14336B，`docs/reference/mutation-ledger.md` 由 40960B 上调到 45056B，三处同批改 doc-budgets 与 baseline。

## Problem

两页任务规格写实施记录前的实测占用是 10175B / 10229B（10240B 的 99.4% / 99.9%，余量 65B / 11B）。M0.3 要求实施记录写进各自页面：日期、文件级改动、验证表（命令 + exit + 计数）、偏差与后续、规则表签核摘要、敌对审核段；两份记录本体实测 4030B / 3743B（约 3.9KB / 3.7KB），压进 65B 只剩「详见别处」的空壳。下沉也没有落点：[M0.3 master](../../../../docs/milestones/M0.3-规则完整化.md) 的「结果」段是阶段级收口，[T-5](../../../../docs/milestones/M0.3/T-5-回归与收口.md) 承载回归与收口，把单任务的实施记录搬过去会让规格与记录分居两页。`docs/AGENTS.md` 的处理顺序是「下沉迁移 → 精简浓缩 → 提额」：本例第一步无落点，第二步要删的正是判据、签名与验证计数这类要被 U7 逐条对照的事实。

变异台账同一批要登记 ML-123–ML-125 三条（T-1 变体缺省/校验、T-2 表尾钳位），台账纪律是只增不减、不重排；登记后实测 41533B，超过 reference 单篇 40960B。台账不能拆（「唯一登记处」是它存在的理由），也不能精简既有行（登记行与期望判死闸是必填内容）。

## Decision

1. 两页任务规格 `limitBytes` 由 10240 改为 14336（14 KB，与 `docs/AGENTS.md` 预算表同值）；`docs/AGENTS.md` 的「单篇 task（`M<N>/T-*`）/ reference」行由 10 KB / 40 KB 改为 14 KB / 44 KB，该行字数不变。提额后两页实测 14175B / 13942B，余 161B / 394B。
2. `docs/reference/mutation-ledger.md` 由 40960 改为 45056（44 KB），只提台账，其它 reference 文档上限不变；提额后实测 41533B，余 3523B。
3. 同批改 `tools/doc-gate/doc-budgets.json` 与 `doc-budgets-baseline.txt` 三处，按 G8 在本 Note 记录理由。

`docs/subsystems/core.md` 不在提额范围：实测 10233B ≤ 10240B，未超限；提额条件仍是「超限才按同一机制处理」。

## Alternatives considered

- **维持 10240B，记录只写指针**：实施记录退化成「详见交接单」，而交接单在 gitignored 的 `.agent-work/`，仓库里就没有「这两个任务改了什么、真跑了什么」的当前事实。
- **把记录下沉到 `reference/` 单页**：reference 有余量，但单任务记录会散成第二棵文件树，「一页规格 + 页内记录」的既有形态（M0.2 T-3/T-7）被拆开。
- **只提 T-2（余 11B）、T-1 继续硬压**：同为提额却还得多删事实，且两页同批写同类记录，形态不一致。
- **提到 12288B**：T-1 页写记录后实测 14175B，12288 差 1887B 装不下；161B 余量是 14336 的实测值，12288 覆盖不了。
- **只登记 ML-123–ML-125 不给台账提额**：只能删既有条目措辞或拆表，前者违反「登记行只增不减」（上一轮已因此被判 P1），后者破坏编号连续性。
- **台账一次提到 49152**：按既有先例每次只提一档（+4096），44 KB 已够本轮并留约 8–10 条余量，避免再写第二篇提额 Note。

## Consequences

- G7 以 `doc-budgets.json` 为准：两页 14336、台账 45056 与 `docs/AGENTS.md` 表行 14 KB / 44 KB 同批生效；G8 以 baseline 为准，json 与 baseline 同步登记，门禁维持 0 errors。
- M0.3 其余三页（T-3/T-4/T-5）仍是 10240B：写实施记录时先按「下沉 → 精简」，超限再按本 Note 机制提额并在同批登记。
- 台账 44KB 是第五次上调（8192 → 16384 → 32768 → 34816 → 40960 → 45056）：下一批登记前先按既有先例核对余量，接近上限时单列新 Note 而不是在本篇续写。
- `.agent-work/m03t1t2/check-t1.ps1` 的 T-1 预算断言按 `doc-budgets.json` 取上限（14336），与门禁同源。
- 预算变更属门禁规则变更：评审按 G8 对照 json、baseline、本 Note 与 `docs/AGENTS.md` 四处一致。
