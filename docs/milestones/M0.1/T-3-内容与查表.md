## 0. 基础类型（本任务先定义，T-4 使用）

```csharp
namespace Mahjong.Core.Rules;
public enum SuitType : byte { Character = 1, Dot = 2, Bamboo = 3, Wind = 4, Dragon = 5 }
public readonly record struct TileType(ushort Id, SuitType Suit, byte Rank);
public readonly record struct Tile(ushort Id, TileType Type) { public const ushort UnknownId = 0; }
```

> Tile/Zone/手牌等运行期模型由 T-4 定义；本任务只定义内容与查表需要的三个类型，避免 T-3↔T-4 循环依赖。

## 1. 内容文件

目录 `content/`：

- `tiles.json`：34 种牌，id 0–33，顺序固定：
  - Character 1–9（id 0–8）、Dot 1–9（9–17）、Bamboo 1–9（18–26）、Wind 1–4（27–30）、Dragon 1–3（31–33）。
  - 红中 = Dragon rank1 = id 31，作为鬼牌。
- `suits.json`：`Character/Dot/Bamboo` rankCount=9、amountOfEachRank=4、allowedSequence=true；`Wind` 4/4/false；`Dragon` 3/4/false。
- `skills.json`：4 个技能 `id 1=Pong、2=Kong、3=SelfDrawn、4=SelfDrawnWith7Pairs`。
- `tables/`：6 个 `.bytes`（已存在，禁止改）。
- `manifest.json`：内容清单（见 §1.1）。

Schema（字段名固定）：

````json
// tiles.json
{ "version": 1, "tiles": [ { "id": 0, "suit": "Character", "rank": 1 } ] }
// suits.json
{ "version": 1, "suits": [ { "suit": "Character", "rankCount": 9, "amountOfEachRank": 4, "allowedSequence": true } ] }
// skills.json
{ "version": 1, "skills": [ { "id": 1, "name": "Pong" } ] }
````

物理牌 id：`typeId * 4 + copy + 1`，copy 0–3；共 136；`0` 保留给 Unknown。

### 1.1 manifest 与 contentHash

`content/manifest.json`：

```json
{ "version": 1, "files": { "suits.json": "<sha256hex>", "skills.json": "<sha256hex>", "tables/ai_dictionary_dragon.bytes": "<sha256hex>", "tables/ai_dictionary_normal.bytes": "<sha256hex>", "tables/ai_dictionary_wind.bytes": "<sha256hex>", "tables/dictionary_dragon.bytes": "<sha256hex>", "tables/dictionary_normal.bytes": "<sha256hex>", "tables/dictionary_wind.bytes": "<sha256hex>", "tiles.json": "<sha256hex>" }, "contentHash": "<64 hex>" }
```

算法：

1. 清单固定 = 3 个 JSON + 6 个 `.bytes`（路径相对 `content/`）；对每个文件算 SHA-256（小写 hex）；
2. 按路径升序拼 `v1\n` + 每行 `path=hash\n`；
3. 对整串 SHA-256，取 **32 字节摘要**：`ContentHash` 暴露原始 32B，`ContentHashHex` 给日志/显示；协议/回放传原始 32B，不传 hex 字符串。
4. 清单里的 `contentHash` 与重算值不一致 → 启动失败。

> 换任何一张表或 JSON，contentHash 必变；`rulesVersion` 由规则兼容性单独决定（M0.1 定义常量 1，变更需 Note）。

启动时校验：文件存在、JSON 可解析、id 连续、suit/rank 合法、每种 4 张；失败抛可读异常并打印文件路径。

## 2. 查表读取（手写 MessagePack 子集，不引第三方）

不要引入 MessagePack-CSharp/protobuf-net；实现 `Mahjong.Core.Content.Tables.MsgPackLite`，只支持本数据用到的编码：

- positive fixint（0x00–0x7f）、uint8/16/32/64；
- **fixarray（0x90–0x9f）**、array16/32；**fixmap（0x80–0x8f）**、map16/32；
- bool、float64；
- 其他类型（str/bin/nil/negative）遇到即抛 `InvalidDataException`。
- 本数据外层是 `0x91`（array(1)）+ `0xdf`（map32；wind/dragon 用 `0xde` map16），行列表与行是 fixarray；解析器必须按长度读，不能假设固定长度。

文件结构：`array(1) -> map<ulong, list<row>>`。

| 表 | row |
|---|---|
| `dictionary_normal/wind/dragon` | `[needJoker:int, hasPair:bool, hasWin:bool, winningRanks:int[]]`（数组长度 9/4/3） |
| `ai_dictionary_normal/wind/dragon` | `[hasPair:bool, probability:double]` |

API：

````csharp
namespace Mahjong.Core.Content.Tables;
public readonly record struct WinRow(int NeedJoker, bool HasPair, bool HasWin, int[] WinningRanks);
public readonly record struct AiRow(bool HasPair, double Probability);
public sealed class TableCatalog
{
    public static TableCatalog Load(string tablesDirectory);
    public bool TryGetWinRows(SuitType suit, ulong key, out IReadOnlyList<WinRow> rows);
    public bool TryGetAiRows(SuitType suit, ulong key, out IReadOnlyList<AiRow> rows);
}
public static class TableKey { public static ulong Encode(ReadOnlySpan<byte> rankCounts); }
````

- `TableKey.Encode`：`cur = cur * 10 + count`，rank 顺序；normal 9 位、wind 4 位、dragon 3 位。
- `suit` 映射：Character/Dot/Bamboo → normal；Wind → wind；Dragon → dragon。
- 加载校验：重复 key、行长度不符、尾随字节、数组头溢出 → 报错。
- 内存：一次读入文件，逐行插入 `Dictionary<ulong, WinRow[]>`；不允许每 tick 分配。

## 4. API 与 AOT

- `ContentCatalog`：`Mahjong.Core.Content`；`Load(directory)`、`TileTypes`、`Suits`、`Skills`、`ContentHash`、`GetTileType/GetSuit/GetSkill`。
- 内容 JSON 用 source-generated `JsonSerializerContext`；禁止反射序列化。
- **路径解析** `ContentPaths.Resolve()`：优先环境变量 `MAHJONG_CONTENT_DIR`；否则 `AppContext.BaseDirectory/content`；否则从当前目录向上找 `content/`；都找不到抛可读异常。
- **Android/M5**：Client 用 Godot `FileAccess` 把 pck 内 `content/` 解到 `user://content/`，再把该目录**显式传给** `ContentCatalog.Load(path)`；Core 不引用 Godot，也不猜 `res://`。
- 查表读取纯 IL、无反射；AOT 安全。
- 冷加载耗时记录到 M0.1 结果（Stopwatch，三次取中位数）。

## 5. 验收

1. `dotnet test`：schema/校验/TableKey/contentHash/7 条 fixture 全过。
2. 故意破坏 manifest/字段/id/表尾 → 报错可读。
3. AOT 编译的 Client `--smoke` 启动时加载内容与表并打印 `CONTENT OK <hash>`，退出 0（T-6 验证）。
4. AOT 导出目录含 `content/`（T-6 脚本复制）；缺失时启动报错指向 `MAHJONG_CONTENT_DIR`。
