# Agent Note: M4 美术成品化与发布验收

Status: implemented — M4 任务与验收已按此拆分：T-4 音频/设置/导航、T-5 素材/UI、T-6 发布就绪。

## Problem

M4 原来只有一条 T-4“音频/基础美术/设置与收口”，验收是“音效/设置/导航”，没有素材清单、界面覆盖与截图判据。M0.2–M3 明确用占位 UI，旧项目的 182 张牌面、66 张 UI 元素、18 个头像、10 个技能图标、17 个字体文件与 83 个音频文件没有落点。按原计划，v1 收口时无法回答“UI 是否成品化、哪些界面还占位”。

## Decision

M4 定义为 v1 发布候选：T-4 做音频/设置/导航；T-5 一次性把旧素材套用到全部 v1 界面（主菜单、单机牌桌、局/终局结算、回放、LAN 房间列表/大厅、公网房间码/加入/等待、设置、观战），以 `content/art/manifest.json`、统一 `Theme`、每屏截图与 1280×720/2400×1080 两种分辨率验收；T-6 做发布包与检查单。M0.2–M3 只做占位 UI，不零散套美术；M5 只改布局/安全区，不重做美术。素材版权在 T-5 开始前书面确认，未确认即阻塞。

## Alternatives considered

- 维持“基础美术”：工作量小，但 v1 仍是一堆占位控件，不能称为可发布成品；用户要的正是成品化。
- 每个里程碑顺手换一点美术：早期界面还会大改，重复劳动，也难有统一 Theme 与验收。
- 单独开 M6“美术/发布”里程碑：M4 已是 v1 收口，新增阶段会打乱 M5 依赖；M5 是 post-v1 移动端，不适合承接桌面成品化。
- 等 M5 移动端再统一套美术：桌面 v1 先发布不了，移动端布局还会二次改 UI。

## Consequences

M4 工期增加 T-5/T-6；M4 前置新增“资产清单与版权确认”。M0.2–M3 的 UI 必须走 Theme/锚点，不能写死字体/颜色（DESIGN §7.4）；M4 收口判据变成“全部 v1 界面无占位 + 发布检查单”，而不只是功能可用。美术/音频/字体是客户端资源，不进 contentHash，服务端不需要分发。
