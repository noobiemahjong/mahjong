# T-1 胡牌与七对（实施规格）

状态：见任务表
依赖：M0.1（T-3 查表、T-4 模型）
对应 master：[M0.2](../M0.2-单机可玩闭环.md)
验收：胡/不胡/七对/鬼牌补齐金标用例全过。

## 1. API

`Mahjong.Core.Rules`：

````csharp
public interface IWinChecker
{
    bool IsWin(IReadOnlyList<Tile> hand, IReadOnlyList<Meld> melds, TileType joker);
    IReadOnlyList<TileType> GetWinningTypes(IReadOnlyList<Tile> hand, IReadOnlyList<Meld> melds, TileType joker);
    bool IsSevenPairs(IReadOnlyList<Tile> hand, TileType joker);
}
public sealed class WinChecker : IWinChecker { public WinChecker(TableCatalog tables); }
````

`joker` 参数取自 `ContentCatalog.Joker`，由 `content/rules.json` 的鬼牌配置决定。

## 2. 算法

1. 把牌按 `SuitType` 分成 5 组 rank 计数；**当前鬼牌（`ContentCatalog.Joker`）不进入 rank 计数**，只作为万能牌；当前鬼牌不能当普通箭牌参与顺子/刻子判定。
2. 副露按“已固定 3 张”从手牌扣除（不参与判定，只影响张数合法性）。
3. 每花色用 `TableKey.Encode` 得 key，`TableCatalog.TryGetWinRows` 取候选行；无候选该花色不可胡。
4. 跨花色回溯：逐个花色选一行，累加 `NeedJoker`，记录 `HasPair`；同一花色多行都要试。终态要求**恰好一个将**（HasPair=true）或鬼牌补齐一个将。
5. 终态：剩余鬼牌满足 `(joker % 3 == 0 && hasPair) || (joker % 3 == 2 && !hasPair)` 即胡。
6. `GetWinningTypes`：对 34 种牌逐一尝试加入（张数 <4），能胡则返回；用于胡牌提示/结算。
7. 七对：恰好 14 张（含副露则为 0 副露）；剔除鬼牌后按 `Type.Id` 排序，两两配对；不成对消耗 1 张鬼牌；剩余鬼牌任意；**必须完整回溯**（不能只回退一位）。
8. 副露/牌数非法（手牌 + 3×副露 ≠ 14）直接 false。

## 3. 测试

- 标准胡（4 面子 + 将）、单鬼补顺、多鬼、无鬼、七对、七对带鬼、不胡、副露胡。
- 与 7 条查表 fixture 对齐（M0.1 T-3）。
- 同输入重复调用结果一致；不分配跨 tick 缓存。
