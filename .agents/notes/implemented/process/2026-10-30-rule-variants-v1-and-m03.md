# Agent Note: 规则变体进 v1 与 M0.3

Status: implemented — D20/D22 与 M0.3 计划已落地，规则表待逐条评审。

## Problem

前一版决策把连庄奖励、跟庄、中马、承包、抢杠、12 张放到 post-v1，理由是 M1/M4 没有对应任务、M4 要收发布。用户随后拍板这些规则必须在 v1 内；如果继续挂在 M4，回放、金标、协议都要在 M1–M3 之后返工，规则语义也会在发布前抖动。旧项目只有 `ScoreActionType` 枚举占位，没有可抄的完整规则表。

## Decision

全部规则变体进 v1：连庄奖励、跟庄、中马、承包（含杠上开花承包、抢杠承包、12 张落地承包）、抢杠、12 张。新增 M0.3（M0.2 与 M1 之间）一次做完；M0.3 规则表先出草案，由用户逐条评审后定稿；数值走 `content/rules.json`，代码不写死。连庄奖励按连庄次数加成。M0.2 仍是规则子集；M1 的前置改为 M0.3，金标以 M0.3 为准。

## Alternatives considered

- 继续 post-v1：用户否掉；且 M1 之后改规则会作废回放/金标，返工更大。
- 扩进 M0.2：M0.2 已在 T-1 后推进，扩范围会推迟单机闭环收口，规则表也没时间评审。
- 放进 M4：发布前改规则，M4 的成品化与规则验证互相挤占，风险最高。
- 不写规则表直接实现：旧项目没有完整语义，抢杠/承包/中马的口径会各写各的，测试无法手算。

## Consequences

M0.3 新增 T-1 规则表评审、T-2 庄家计分、T-3 抢杠与承包、T-4 中马、T-5 回归收口。M1 及之后的流/回放/金标以 M0.3 的规则与事件为准；`content/rules.json` 与 contentHash 在 M0.3 更新，M0.2 旧金标保留但不对应当前 rulesVersion。抢杠只抢补杠牌，不引入点炮/荣和。
