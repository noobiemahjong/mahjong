状态：见任务表
依赖：T-3
对应 master：[M0.1](../M0.1-工程底座与内核骨架.md)
验收：模型单测全绿；不变量可验证；无 UI/网络依赖。

> **已知偏差**：当前为 `Wall` 69 + `WallTail` 14；目标单牌墙见 [proposed Note](../../../.agents/notes/proposed/architecture/2026-10-30-single-wall-no-reserved-tail.md)，代码未改。

## 1. 命名空间

`Mahjong.Core.Rules`（模型）；`Mahjong.Core.Content`（定义）；不引用 Godot/网络/时钟。

## 2. 类型

> `SuitType / TileType / Tile` 的声明在 [TileTypes.cs](../../../src/Mahjong.Core/Rules/TileTypes.cs)（相等性见 §3），本任务**不重复定义**；本任务新增区域/手牌/副露/局面类型。

````csharp
public enum ZoneKind : byte { Wall, WallTail, Hand, Meld, Discard, Revealed }
public readonly record struct ZoneId(byte Seat, ZoneKind Kind); // Seat = 255 表示公共区

public enum MeldKind : byte { Pong = 1, KongExposed = 2, KongConcealed = 3, KongSupplement = 4 }

public sealed class TileZone
{
    public TileZone(ZoneId id, int capacity = 0);
    public ZoneId Id { get; }
    public int Count { get; }
    public Tile this[int slot] { get; }
    public IReadOnlyList<Tile> Items { get; }
    public void Append(Tile tile);
    public Tile RemoveAt(int slot);
    public bool Remove(Tile tile);
    public int IndexOf(Tile tile);
    public void Clear();
}

public sealed class Meld
{
    public Meld(MeldKind kind, IReadOnlyList<Tile> tiles, bool opened, byte targetSeat);
    public MeldKind Kind { get; }
    public IReadOnlyList<Tile> Tiles { get; }
    public bool Opened { get; }
    public byte TargetSeat { get; }   // 255 = 无
}

public sealed class PlayerState
{
    public PlayerState(byte seat);
    public byte Seat { get; }
    public TileZone Hand { get; }
    public List<Meld> Melds { get; }
    public TileZone Discards { get; }
    public short Score { get; set; }
    public bool IsBanker { get; set; }
}

public sealed class GameState
{
    public GameState();               // 4 座；Wall/WallTail 为空
    public TileZone Wall { get; }
    public TileZone WallTail { get; }
    public PlayerState[] Players { get; }
    public byte CurrentSeat { get; set; }
    public byte RoundNo { get; set; }  // 1..8
}
````

## 3. 不变量与 API

- `TileType`/`Tile` 的相等性**只比 `Id`**：必须手写 `Equals/GetHashCode/==`，不能依赖 `record struct` 的默认逐字段相等。
- id 1–136 唯一，0 仅 Unknown；模型内不用 -1（-1 只用于线上/回放编码的“不可见牌”，读取时映射为 Unknown 或 null）。
- `TileZone`：
  - **只允许尾部追加**（发牌/摸牌是 Append；移除用 RemoveAt）；不得 Insert 到中间，也不得在 zone 内排序；展示排序由 ViewModel 做。
  - 越界/重复 id → 抛 `InvalidOperationException`；`Remove` 找不到牌返回 `false`、`IndexOf` 找不到返回 `-1`（与返回类型一致，便于流程层探测）。
  - 槽位域：手牌 slot = `Hand.Items` 下标；弃牌 slot = `Discards.Items` 下标；命令只携带手牌 slot，`Discarded` 事件的 slot 是弃牌区下标。
- `Meld`：固定 3 张折算（杠的 4 张里 1 张视为补张，不计入 14 张）；补杠**替换**同 `Type` 的既有 `Pong`（`Kind` 改为 `KongSupplement`、4 张），不新增副露。
- `PlayerState`：手牌 Zone、副露 List、弃牌 Zone、分数（short）、是否庄家；不提供排序 API。
- `GameState`：牌墙（头摸）、牌尾（杠补）、四玩家、当前座位、局号（1–8）。
  - `Deal(IRandomSource rng, byte bankerSeat)`：按 §3.1 的确定性步骤初始化 Wall/WallTail 并发牌；`bankerSeat > 3` 抛 `ArgumentOutOfRangeException`。
  - `bool IsWallEmpty { get; }`；`DrawFromWall(byte seat)`、`DrawFromTail(byte seat)`：空墙抛 `InvalidOperationException`（属编程错误，流程层先用 `IsWallEmpty` 判流局，不靠异常做流程）。
  - `void Discard(byte seat, int handSlot)`：从 `Hand` 取 `handSlot` 并 Append 到 `Discards`；越界抛 `InvalidOperationException`。
  - `Meld DeclareMeld(byte seat, MeldKind kind, ReadOnlySpan<int> handSlots, byte targetSeat, int? targetDiscardSlot = null)`：把指定手牌槽位移入副露；`Pong/KongExposed` 需要 `targetDiscardSlot`（从目标座位弃牌区移除），`KongConcealed` 不需要，`KongSupplement` 见上。
- 洗牌：注入 `IRandomSource`，种子显式传入；同 seed 同结果。
  `public interface IRandomSource { uint NextUInt(); }`；PCG32 实现放 `Mahjong.Core.Rules`，构造函数 `Pcg32(ulong seed, ulong stream = 1)`，状态为实例字段，禁止静态。
- 手牌展示排序：单独静态方法 `HandOrdering.SortedForDisplay(IEnumerable<Tile>)`，规则：普通牌按 Type.Id，鬼牌最后；不改 zone。
- 发牌后牌墙总数 = 136 - 4*13 - 1（庄家多一张）= 83；其中 **Wall=69、WallTail=14**（杠从 WallTail 尾部补）。流局判据：**Wall 空即流局**；WallTail 只用于杠补，牌局结束时允许有余额。
- 鬼牌由 `content/rules.json` 指定（`ContentCatalog.JokerRule`，v1 默认红中）；**当前鬼牌不进 rank 计数**，只作万能牌参与胡牌判定；不能当普通箭牌使用，不能打出，也不能作为碰/杠材料。

### 3.1 发牌的确定性步骤（必须按此实现）

````
Deal(rng, bankerSeat):
  order = [1..136] 做 Fisher-Yates：i 从 135 递减到 1，j = rng.NextUInt() % (i + 1)，交换 order[i] 与 order[j]
  WallTail = order[122..136)   // 洗后末尾 14 张
  Wall     = order[0..122)
  按座位 (bankerSeat, +1, +2, +3) mod 4 各发 13 张：从 Wall 头取牌 Append 到手牌
  庄家再从 Wall 头摸 1 张作为第 14 张
  → Wall 余 69 张、WallTail 14 张
````

- 洗牌只发生一次；之后只通过 `DrawFromWall/DrawFromTail` 取牌。
- `j` 用取模（不做拒绝采样）；同 seed、同实现必得同序。

## 4. 测试

- 张数/唯一性/发牌数量/摸打/插入移除/越界/重复 id。
- 同 seed 洗牌两次一致；不同 seed 不同。
- `Deal` 槽位断言：Wall 69 / WallTail 14 / 庄家 14 张 / 三家 13 张，且同 seed 两次全槽位一致。
- `DeclareMeld` 四态：碰/明杠/暗杠/补杠（补杠不新增副露、张数守恒）；`Discard` 手牌槽位与弃牌槽位两个域不混。
- 展示排序不改变原 zone 顺序。
- 模型层无静态可变字段（T-4 提供反射扫描测试，T-5 复跑覆盖 Flow/Session）。

偏差：

- `Tile`/`TileType` 由 `record struct` 改 `readonly struct`：record struct 由编译器合成 `==`/`!=`，自定义即 CS0111，无法满足 §3「手写相等性且只比 Id」；理由见 [相等性 Note](../../../.agents/notes/implemented/architecture/2026-10-29-tile-identity-by-physical-id.md)。
- `Deal` 在规则层按 `content/tiles.json` v1 固定布局由物理 id 还原 `Suit/Rank`（`GameState` 不引用 Content）；`RulesContentAlignmentTests` 是 Rules 下唯一读取仓库 `content/` 的测试，其余规则测试不依赖内容目录；理由见 [确定性发牌 Note](../../../.agents/notes/implemented/architecture/2026-10-29-deterministic-deal-and-pcg32.md)。
- `Meld` 构造防御性拷贝输入集合；`Tiles` 是 Meld 自身存储的实时只读视图（补杠后可见第 4 张）；理由见 [zone/补杠 Note](../../../.agents/notes/implemented/architecture/2026-10-29-zone-append-only-and-meld-upgrade.md)。
- `TileZone.Remove/IndexOf` 找不到返回 `false`/`-1`（与返回类型一致）；越界/重复 id 才抛 `InvalidOperationException`。
- 静态扫描只跳过编译器命名类型（`Name` 以 `<` 开头），并断言手写类型不得带 `[CompilerGenerated]`。

后续（非阻断）：

- `DrawFromWall` 用 `RemoveAt(0)` 为 O(n)：实测 69 张牌墙 + 14 张牌尾共 83 次摸牌合计约 0.74 ms，M0.1 可接受；基准数据留给 T-6。
- `HandOrdering` 为插入排序 O(n²)，手牌 ≤14 张，仅展示层调用。
- 模型不做跨 zone 的 136 张全局唯一性校验（各 zone 内按 `Id` 去重）；全局唯一由发牌与流程保证。
- `CurrentSeat`/`RoundNo` setter 的 `ParamName` 为 `value`（属性 setter 惯例）。
