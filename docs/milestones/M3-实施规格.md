# M3 实施规格

状态：见任务表
对应 master：[M3 计划](M3-公网服务器.md)

## T-1 无头服务器与房间

- `RoomManager` 接口：`Create(name,password?,maxPlayers) -> Room`、`Find(code)`、`Join(code,password,role)`、`Close(code)`、`List()`。
- 房间状态：`Created(60s 宽限) -> Waiting -> Playing -> Closed`；创建后 60s 无人加入才销毁；开局后 4 真人全离线立即销毁（D13）。
- 房间码：6 位大写字母+数字，排除 0/O/1/I；冲突重试 5 次；大小写不敏感。
- 开局：4 座坐满或房主 `Start`；空位 Bot 补；Bot 接管走 M2 T-3。
- 每房一个 `TcpSessionHost` + `GameSession`；单进程多房间；会话单线程轮询。
- 测试：并发建房/加入/销毁；码冲突；状态迁移；Bot 补位。

## T-2 HTTP API

ASP.NET Core Minimal API（服务器 JIT）：

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/rooms` | `{name,password?,maxPlayers=4}` | `{roomCode, host, port, protocolVersion, rulesVersion, contentHashHex}` |
| POST | `/rooms/{code}/join` | `{password?, role}` | `{host, port, roomCode}`；token 在 TCP Welcome 下发 |
| GET | `/rooms/{code}` | — | `{state, players, maxPlayers, host, port}` |
| GET | `/replays` | `?limit=30` | `[{id, createdAt, roomCode, players, size, completed}]` |
| POST | `/replays/{id}/token` | — | `{token, expiresAt, url}` |
| GET | `/replays/{id}?token=` | Range | `.mjr` 字节流 |
| GET | `/healthz` | — | `{ok, rooms, version}` |

- 错误码：400 参数、404 不存在、409 满/已开局、429 限流、401 密码/token。
- 限流：同 IP 建房 1 次/秒；请求体 ≤8KB。
- 测试：全端点集成测试；错误码；Range 206。

## T-3 版本握手

- 复用 protocol Hello/Welcome/Reject；比较 `protocolVersion/rulesVersion/contentHash(32B)`；失败 reason 0/1/2。
- 客户端 UI 显示拒绝原因；不自动重试不兼容版本。
- 测试：三种不匹配各一例。

## T-4 回放保留与下载

- 会话结束写 `replays/{yyyyMMdd-HHmmss}-{roomCode}-{replayId}.mjr`（M1 格式），完成标志 flags bit0；未完成也落盘但标 0。
- `replays/manifest.json`：`[{id,file,createdAt,roomCode,players,size,completed,sha256}]`；启动校验/清理孤儿。
- 保留最近 30 局（可配），按 createdAt 淘汰；删除文件+manifest。
- token：32B 随机 base64url，10 分钟、一次性；成功下载后失效；Range 续传用同一 token 直到过期。
- 测试：第 31 局淘汰；过期/重复 token；Range 续传；损坏文件 500。

## T-5 部署与收口

- Dockerfile 多阶段：`sdk:10.0` build → `aspnet:10.0` runtime；`COPY content/` 到 `/app/content`；`MAHJONG_CONTENT_DIR=/app/content`。
- 环境变量：端口、最大房间、回放目录、保留数、日志级别；卷挂载 `/app/replays`。
- 日志 JSON Lines；每房间 sessionId；不记录手牌内容。
- 命令：`docker build -t mahjong-server .`、`docker run -p 8080:8080 -p 9000:9000 -v ...`；`curl` 建房/查询；3 客户端跨网 + 1 Bot。
- 文档：architecture、subsystems/server.md、cookbook/server.md、M3 结果/运维。

## T-6 客户端接入

- Godot：房间码输入/加入/房间列表；连接失败/拒绝原因展示；赛后回放列表、下载、打开 M1 播放器。
- 路径：`Mahjong.Client/Network/`、`Mahjong.Client/UI/RoomJoin.tscn`；HTTP 用 `HttpClient`（AOT 安全）。
- 验收：手工清单——建房/加入/拒绝/下载/播放；3 客户端跨网。
