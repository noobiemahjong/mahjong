# M3 实施规格

状态：未开工
对应 master：[M3 计划](M3-公网服务器.md)

## T-1 无头服务器与房间

- `Mahjong.Server` 控制台：读 appsettings（端口、最大房间、回放目录、保留数、日志级别）。
- `RoomManager`：创建房间（6 位字母数字码，排除易混字符）、按码查找、加入鉴权（可选密码）、空闲回收。
- 房间内复用 M2 `TcpSessionHost` + `GameSession`；4 真人全离线立即销毁（D13），已开局则落盘未完成回放。
- 单进程多房间；会话单线程轮询；网络 I/O 独立。
- 测试：并发建房/加入/销毁；码冲突重试；配置非法拒绝启动。

## T-2 HTTP API

- ASP.NET Core Minimal API（服务器 JIT，无 AOT 约束）。
- `POST /rooms`：{name,password?,maxPlayers=4} → {roomCode, host, port}；`GET /rooms/{code}` → 状态/人数/版本；`GET /healthz`。
- 错误码：404 房间不存在、409 已满/已开局、400 参数错。
- 限流：同 IP 建房/秒 1 次；请求体 ≤8KB。
- 测试：API 集成测试；房间码路径；错误码。

## T-3 版本握手

- 复用 [protocol](../specs/protocol.md) 的 Hello/Welcome/Reject；服务端比较三元组，失败带原因码（协议/规则/内容/房间满/密码错）。
- 客户端 UI 显示拒绝原因；不自动重试不兼容版本。
- 测试：三种不匹配各一例；匹配通过。

## T-4 回放下载与保留

- 会话结束写 `replays/{id}.mjr`（M1 格式）；`manifest.json` 记录时间/房间/玩家/大小/哈希。
- 保留最近 30 局（可配）；启动时按 manifest 清理孤儿/超限。
- `GET /replays/{id}?token=...`：一次性 token（10 分钟、成功即失效），支持 Range；不绑账号。
- 测试：第 31 局淘汰；过期/重复 token 拒绝；Range 续传。

## T-5 部署与收口

- Dockerfile（mcr.microsoft.com/dotnet/runtime:10.0）+ 卷挂载 `replays/`；环境变量覆盖配置。
- 日志：JSON Lines；每房间 sessionId；不记录手牌内容。
- 跨网验收：3 客户端（不同网络）打完一场；断线重连；回放下载。
- 文档：architecture、subsystems/server.md、cookbook/server.md、M3 结果与运维说明。
