# M0：工程骨架与单机最小闭环

状态：未开工
开始日期：—　收口日期：—

## 1. 目标

一句话：**用一套能长期维护的工程骨架，在本地跑通「1 真人 + 3 Bot、8 局完整流程、规则子集」的最小可玩闭环，并把质量底座（测试/AOT/CI/doc-gate）一次建好。**

M0 的完成不是「代码能跑」，而是：换一个会话/换一个人，能在 30 分钟内按文档把工程跑起来、打一局、跑测试、导出 AOT、看懂代码结构。

## 2. 范围

### 2.1 包含

- 仓库与解决方案骨架：5 个工程、目标框架、依赖方向、构建/测试命令。
- 内容底座：牌/花色/技能配置、6 个查表加载、contentHash。
- 规则子集：牌与区域、摸打、碰/杠（明/暗/补）、自摸、七对、流局、计分、庄家轮换、8 局循环。

- 本地会话：4 座、3 Bot、本地回环传输、事件流（内部）。
- Godot 客户端最小闭环：能看牌、能操作、能看结算、能重开。
- 质量底座：单测、金标对局、AOT 冒烟、CI、doc-gate、提交钩子。
- 文档：architecture 更新、4 个子系统页、cookbook（构建/运行/AOT）、M0 结果与已知缺口。

## 3. 「工程骨架」具体包含什么

1. **仓库层**：`.gitattributes`（LF/二进制）、`.editorconfig`、`global.json`（SDK 10.0.x）、`Directory.Build.props`（TFM/Nullable/LangVersion/警告）。
2. **解决方案**：`Mahjong.sln` + 5 个工程：
   - `Mahjong.Core`（Rules/Flow/Protocol/Content；不引用 Godot）
   - `Mahjong.Session`（本地/权威会话）
   - `Mahjong.Client`（Godot.NET.Sdk/4.7.2，net10.0，PublishAot）
   - `Mahjong.Server`（net10 控制台，M0 只保证可构建/启动）
   - `Mahjong.Tests`（xUnit，不引用引擎）
3. **依赖方向**：Client → Core；Server → Session → Core；Tests → 全部；Core 不反向依赖。
4. **组装方式**：手写 Composition Root（不引入反射容器）；日志用 `Microsoft.Extensions.Logging`；配置从 `content/` 读。
5. **Godot 工程**：`project.godot`、`Startup` 场景、`LocalGame` 场景、主场景设置、导出预设（Windows）。
6. **AOT 底座**：`PublishAot`、`TrimmerRootAssembly`（Client、Core、GodotSharp）、AOT 冒烟脚本骨架。
7. **质量底座**：`tools/doc-gate`（G1–G12）、commit-msg 钩子、CI（构建 + 单测 + doc-gate，无 paths 过滤）。
8. **命令**：`dotnet build`、`dotnet test`、`pwsh tools/doc-gate/doc-gate.ps1 -Fail`、`pwsh tools/aot-smoke/aot-smoke.ps1`。

## 4. 「规则」具体包含什么

### 4.1 牌与区域

- 34 种牌：万/筒/条各 1–9，风 东/南/西/北，箭 中/发/白；每种 4 张，共 136 个物理 id。
- 鬼牌固定红中；手牌插入按 id 有序、鬼牌归位。
- 区域：牌墙/手牌/副露/弃牌/亮牌；槽位用插入序，协议/流内不排序。

### 4.2 动作与技能

| 动作 | M0 要求 |
|---|---|
| 摸牌/出牌 | 牌墙头摸、尾补；手牌合法性校验 |
| 碰 | 手牌 2 张同 Type 非鬼 + 目标弃牌；碰后强制出牌 |
| 明杠 | 手牌 3 张同 Type 非鬼 + 目标弃牌 |
| 暗杠 | 手牌 4 张同 Type 非鬼 |
| 补杠 | 已有碰的 3 张 + 手牌第 4 张 |
| 自摸 | 胡牌表判定，含鬼牌；结算 |
| 七对 | 独立判定；倍数 ×2 |
| 过 | 响应窗口放弃 |
| 流局 | 牌墙耗尽 |

响应窗口：胡 > 杠/碰；多个合法响应按服务端到达顺序，先到先得，结果写入流（M0 本地也走同一路径）。

### 4.3 计分与轮次（M0 子集）

- 自摸：无鬼 4 / 有鬼 2（每家付）；七对 ×2；杠上开花 ×2。
- 杠：明杠 +3/放杠者 -3；暗杠 +6/其余各 -2；补杠 +3/其余各 -1。
- 流局：本局分数回滚。
- 8 局；庄家随机起，非庄胡牌则赢家坐庄；终局总分/名次。
- **不含**：承包/抢杠/12 张落地/跟庄/中马——M1/M4 补。

### 4.4 Bot（M0）

- 只要求**合法 + 能打完**：能胡则胡；能碰/杠按简单规则；出牌优先摸到的牌，否则按手牌顺序第一张合法牌。
- 不接 AI 牌效表；不拟人化延迟（会话层固定 300ms）。
- 目标：4 Bot 8 局自动跑完，不出现非法动作/死循环。

## 6. 任务验收

### T-1 工程骨架

- `dotnet build` 0 warning、0 error；`dotnet test` 可跑（空用例也算通过）。
- Core 无 Godot 引用（编译期/反射测试）；Client TFM net10、PublishAot/root 配置齐全。
- Godot 能打开空场景运行；Server 启动后正常退出。

### T-2 质量底座

- 故意制造坏链接/BOM/CRLF/超预算/错误 Note 路径，doc-gate 必须红；修复后绿。
- commit-msg 拒绝超 50 字标题、超 10 行 body；通过用例绿。
- CI 在 push/PR 上跑构建+单测+doc-gate，无 paths 过滤。

### T-3 内容与查表

- 6 个 `.bytes` 全部加载；抽样 key（见 `docs/TABLES.md`）返回值与解码结果一致。
- contentHash 稳定；缺失/损坏内容启动报错可读。
- AOT 导出后仍能加载（不依赖反射 resolver）。

### T-4 / T-5 / T-6 / T-7 / T-8

- 每个任务至少覆盖：正常路径 + 一条非法路径 + 一条边界。
- T-5：同脚本运行两遍状态哈希一致；两个会话交错 tick 不串状态。
- T-6：胡/不胡/七对/鬼牌补齐/听牌（可选）金标用例。
- T-7：胡优先于碰杠；非法碰/杠被拒；碰后强制出牌。
- T-8：自摸/七对/三种杠/流局回滚/庄家轮换用例；8 局逻辑模拟能结束。

### T-9 Bot

- 4 Bot 自动 8 局完成；无非法动作；同 seed 两遍结果一致；单局 Bot 决策 <1ms。

### T-10 本地会话

- 脚本化人类输入可走完 8 局；4 Bot 可走完；两个 Session 交错运行状态隔离。
- 事件流可被客户端消费；无网络代码路径。

### T-11 Godot 最小闭环

手工清单全过：

1. 启动 → 本地对局 → 发牌 → 轮流出牌。
2. 能看到：自己手牌、四家弃牌/副露、剩余牌数、分数、当前轮到谁。
3. 能操作：出牌、碰、杠、胡、过；非法操作不可点。
4. 一局结束显示结算；8 局结束显示总分/名次；可返回/重开。
5. 连续两局无崩溃、无卡死、无控制台红字。

### T-12 收口

- Windows 导出 AOT，独立 exe 完成一局（不依赖 Godot 编辑器）；stderr 为空。
- 性能基线记录：tick p99、8 局逻辑模拟耗时、AOT 启动到可操作耗时。
- 文档：`architecture.md` 更新为实际结构；`subsystems/` 4 页（rules/flow/session/client）；`cookbook/` 3 篇（构建/运行/AOT 导出）；M0 结果与已知缺口。
- 代码无「TODO 未登记」；所有缺口在 M0 结果里列出并指定去向。

## 7. M0 完成定义（全部满足才算收口）

1. **构建/测试**：`dotnet build` 0 warning；`dotnet test` 全绿；doc-gate 绿；CI 绿。
2. **单机闭环**：1 真人 + 3 Bot 能完成 8 局（规则子集），结算/重开正常；手工清单全过。
3. **自动化**：4 Bot 8 局自动完成；同 seed 两次最终状态哈希一致；关键规则用例覆盖。
4. **AOT**：Windows 独立 exe 完成一局；stderr 空；启动到可操作 < 3s（开发机基线）。
5. **性能**：10Hz 下逻辑 tick p99 < 1ms；8 局逻辑模拟 < 5s；连续两局无内存持续增长。
6. **文档**：architecture + 4 子系统页 + 3 篇 cookbook + M0 结果/已知缺口；无过期状态描述。
7. **范围守门**：没有把网络/回放/观战/移动端混进 M0；未实现项在 §2.2 有明确去向。
