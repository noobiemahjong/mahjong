## 2. 规则

- **碰**：`TargetCard` 是对方最后弃牌、手牌同 `Type` 非鬼 ≥2；`Commit` 声明 `MeldKind.Pong`、不摸牌、`CurrentSeat = Source.Seat`（强制出牌）。
- **杠**三态按固定序判定：明杠（有目标弃牌 + 手牌 ≥3）→ 补杠（已有同 `Type` 碰 + 手牌 ≥1，`DrawnTile` 牌种先作提示）→ 暗杠（无同 `Type` 碰 + 手牌 ≥4）；三态都在声明副露后从墙尾 `DrawFromTail` 补 1 张并 `CurrentSeat = Source.Seat`。
- **墙空**：三种杠 `Validate=false`、`Commit` 抛 `InvalidOperationException` 且状态不变；「牌墙空即流局」由流程层判。
- **自摸**：`SelfDrawnSkill.Validate = IsWin && !IsSevenPairs`，`SelfDrawnWith7PairsSkill.Validate = IsSevenPairs`（七对优先、不双算）；`Commit` 只复校验、不改状态，分数与局结束归 T-3/T-5。
- **Commit 边界**：`Validate` 不改状态；`Commit` 先完整复校验再一次性改状态，失败抛 `InvalidOperationException` 且状态不变。
- **过**：提交 `CommandVerb.Pass` 走 `TryPass`，不是「不提交」；胡只在摸牌后自摸（含七对、杠后自摸），不进弃牌响应窗口，抢杠在 M0.3。
- **仲裁键**：`(杠 > 碰, arrivalSeq 升序, 座位升序)`；杠在任何 tick 压过碰，跨 tick 先到先得只在同优先级内成立；`arrivalSeq` 是到达批次（逻辑 tick），同 tick 同值、跨 tick 单调递增，`arrivalSeq > deadlineTick` 判迟到。
- **窗口**：`Open` 按候选顺序分配连续 `requestId`、单次使用；`Close` 在 `tick >= deadlineTick` 或全体已应答时逐座产出 `RequestOutcome`（胜者 `Answered`、竞争落败 `Cancelled`=2、Pass 者 `Answered`、未应答者 `TimedOut`=1），重复 `Close` 幂等；细节见 [flow.md §8](../../subsystems/flow.md)。
- 鬼牌不可打出、不可作碰/杠材料，`joker` 由构造注入、`default(TileType)` 表示无鬼；响应 deadline 默认 150 tick（10Hz）；牌墙单墙、发牌后 84、首回合摸后 83。

## 3. 校验器

`CardAndSkillVerifier.Verify(state, player, skill?, card?, targetCard?)` 只读、全部满足才 true：null 参数抛 `ArgumentNullException`；`player` 必须与 `state.Players` 同引用；出牌要牌在手中、非鬼、轮到自己、折算 14 张；技能值必须已定义；目标牌必须是某座位 `Discards` 最后一张且仅一处；折算张数碰 13、杠 13 或 14、自摸/七对 14；最后以 `card` 作 `DrawnTile` 构造 `SkillContext` 调技能 `Validate`；`Tile.UnknownId` 的 `card` 按未提供处理。逐项检查顺序与失败面见 [core.md §5](../../subsystems/core.md)。

服务端/本地会话对每个提交动作再校验一次；失败不改变状态并记日志。

## 4. 测试

- 碰/明杠/暗杠/补杠/自摸/七对/过 各一例；非法动作被拒；自摸不走响应窗口；弃牌后无人可响应则下家摸牌。
- 三家同时可碰/杠：杠优先；同一 tick 内同优先级按座位号升序，跨 tick 先到先得；败者收到取消（outcome=2）。
- 碰后强制出牌；杠后补牌来自牌墙末尾；牌墙空即流局。
