# 单元任务书模板（cell-brief，含交接单；与任务内容无关）

> 用法：Lead 每开一个会话单元，复制本模板填 0–9 段，作为该单元唯一开工依据；单元结束前按 §8 写交接单。
> 上限：**≤80 步 / ≤150K 上下文 / 一个产物**（口径以 `docs/development.md` §团队与委派为准）。到线即落盘交接，不续。
> 到线时产物未完成：交接单首行标「**未完成：缺哪几项**」，该单元**不计 PASS**，必须续派补完；不得让下一个单元在不知情下继承半成品。

## 0. 标识

- 单元号：`U-<n>-<角色>`（任务书文件名 `units/U-<n>-<角色>.md`）
- 角色与承载：`<角色>` —— 承载按 CONTRACT §3 的承载列填（默认 subagent），临场不得改；要改先回契约改并说明理由。
- 上游单元：`<交接单路径，无则写「无」>`

## 1. 唯一产物

- 路径：`.agent-work/<本批标识>/<产物名>`
- 产物组织：按 CONTRACT §5，或「见上一交付物 对应节」
- 不产出第二个文件（临时脚本除外，命名 `*.ps1`）
- **返工单元（round-2）**：任务书必须附 findings 清单（位置 / 期望值 / 判据）+ 原单元交接单；只改清单覆盖的位置，清单外问题上报不自行改；产物末尾附「findings 逐条闭环表」

## 2. 上下文清单（只读这些，别多读）

| 文件 | 读法 | 用途 |
|---|---|---|
| `.agent-work/<本批标识>/CONTRACT.md` | 整篇 | 口径与所有权 |
| `<目标文档>` 的对应节 | 先按规模检索，再按范围取 | 范围与判据 |
| `.agent-work/<本批标识>/evidence-*` | 按 key 取 | 上游采好的证据 |
| 根 [AGENTS.md](../../../AGENTS.md)、[docs/AGENTS.md](../../../docs/AGENTS.md)、[tools/AGENTS.md](../../AGENTS.md) | 按改动面取 | 仓库规矩 |

> **审核单元**：表里的上游产物只作**待核对象**，不作前提；被引用的事实一律回源核验，冲突先报 Lead，不就地改。
> 审核产出文件**头部四行必填**：`轮次 / 步数 / 上下文量级（自报）/ 被审产物版本标识`——Lead 据此判断「审核会话超期」（>80 步、avg >200K、同一产物第 4 轮）。
> **「只读这些」限制的是无关探索，不是核验**：需要核事实时读原始数据 / 客户端 / 基线与复用点是被允许且鼓励的；为省事跳过回源才算违规。

## 3. 口径

- 编号体系：按 CONTRACT §4
- 每条结论带证据锚点（「文件 §小节」、类型/方法符号、脚本输出）与该批使用的强度标记（L1/L2/L3 / 测试与门禁判据）；缺证据写「待核」并说明缺哪侧与检索路径，禁止用邻条推断。
- 引用本仓代码不写源码行号；写不出依据的项删掉或列进「待裁决」并报 Lead。

## 4. 依据（每一条都要能指回源）

| 项 | 依据写法 |
|---|---|
| 范围 / 清单 | `<目标文档> §<范围节>` 或 `plan.json` 的 rows |
| 产物组织单位（章节 / 模块 / 表 / 配置） | `<上一交付物> §<对应节>` |
| 公式 / 推导 / 复用点 | `<上一交付物> §<小节>` 或代码符号锚点 |
| 编号规则 | `CONTRACT §4` |
| 验收命令 | `CONTRACT §6` |

写不出依据的项 = 幻觉，删掉或列进「待裁决」并报 Lead。

## 5. 工具纪律（批量与输出）

- 判据：**这一步的输出，下一步会不会直接用？** 会就合进同一个 `run_code`；本身是原子判断就单独一步。禁止的是「先看一眼再决定」的空转步。
- 同类多样本一律用批量接口（客户端数据用批量读、脚本侧一次查多个目标）；先看规模再取内容。
- `console.log` 总量 ≤2K 字符；大块数据落盘，只回传路径 + 3 行摘要 + 关键计数。
- 校验用脚本一次跑完（`pwsh -File .agent-work/<本批标识>/check-*.ps1`），不靠反复肉眼比对；结论贴脚本输出。
- **同一时点的多条验证，放进同一个 `run_code`**：PTC 模式下**一步 = 一次完整上下文重发**，所以「跑几条命令」不要紧，「开几个步骤」才要紧。形态（一个 `run_code` 里顺序跑，任一失败即停，只回摘要）：

```ts
const cmds = [
  "dotnet build Mahjong.sln -v q --nologo",
  "dotnet test Mahjong.sln --no-build --filter \"<L1 过滤>\" --nologo",
  "pwsh -File tools/doc-gate/doc-gate.ps1 -Fail",
];
for (const c of cmds) {
  const r = await tools.ops_bash({ command: c + " 2>&1 | tail -20", workdir: "<仓库根>", timeoutMs: 600000 });
  console.log("$ " + c + "\n" + (r.stdout?.text ?? "").trim().split("\n").slice(-6).join("\n") + "\nexit=" + r.exitCode);
  if (r.exitCode !== 0) break;
}
```

  **什么时候不该用上面这套（别过度合并）**：
  - 只想确认**能编译** → 一步只跑 `dotnet build`，不要顺带跑测试与门禁；
  - 只想确认**某个测试类** → 一步只跑该 filter，不要整批；
  - **中间态不要跑 doc gates**（未完成的文档必然红，白费一步）；门禁归收口前那一步。
  判据：**一个步骤只回答一个问题**；同一问题的多条命令才合并，不同问题不要硬塞。
- 同一文件本单元 `read` 超过 3 次即停：改脚本一次抽全，或把结论写进产物再引用（**引用未核结论时标注「待核」**，不得当成已核）。

## 6. 禁止事项

- 不写别人名下的文件（清单见 CONTRACT §3）；需要别人补 → 发消息并报 Lead。
- 不 commit、不 push、不改只读基线目录、不改旧交付物本体（发现冲突报 Lead）；不手改 `content/tables/*.bytes`。
- 不悄悄简化；确需简化 → 在产物里写清缺什么、对照的基线位置、恢复时机，并报 Lead。
- 常规任务不跑变异矩阵：只把变异点登记进 [变异台账](../../../docs/reference/mutation-ledger.md)，结果列写「未跑」，汇报写「已登记、未跑」；不得改实现做变异，也不得把未变异的用例写成已绿。
- 外部参考仓只读（见根 `AGENTS.md` 红线）；MCP 写操作必须属于已确认任务，工具不得隐式触发。
- 不伪造绿灯：没跑写「未跑」；门禁证据附命令与退出码。

## 7. 验收（通过才算完成）

```pwsh
pwsh -File .agent-work/<本批标识>/check-<x>.ps1        # 期望：<输出> 且 exit 0
pwsh -File tools/doc-gate/doc-gate.ps1 -Fail        # 文档类产物收口，期望 exit 0 / 0 ERROR
```

- [ ] 覆盖项/轴与契约一致（脚本断言：条数 == CONTRACT §2 声明值）
- [ ] 每条结论都有锚点与强度标记（脚本断言：锚点缺失数 == 0）
- [ ] 编号连续 / 无重复（脚本断言：集合 == 期望集合）
- [ ] 无「待核」项缺检索路径

> 验收脚本必须含上面三条**结构性断言**；脚本本身会被审核单元与 Lead 抽看——**断言写宽松 = 视为未验收**。

## 8. 交接单（本单元最后一个动作）

写到 `.agent-work/<本批标识>/handoff-<单元号>.md`，四段缺一退回；「已排除」不许空。原则：**给路径与命令，不给「我确认过了」**。

**未完成的判断不得当结论交付**：手上没走完的推理、没核实的读数，写进「待办」或「风险」，不要写成结论让下一个单元继承。

```
## 单元：<单元号> · 产物：<路径>
## 1. 结论   已确认的 3–5 条：结论 | 证据锚点 | 强度
## 2. 已排除 试过但走不通的路 | 为什么走不通 | 试到哪一步（不许空）
## 3. 待办   「文件 §小节」+ 要做什么 + 验收判据；建议下一个单元及其原因
## 4. 风险   缺哪侧证据 / 需要谁裁决 / 判错会影响哪几条
```

## 9. 结束动作（顺序不可变）

1. 跑验收命令，输出贴产物末尾
2. 写交接单
3. 回报按承载分岔：**teammate** → `send_message` 给 Lead；**subagent** → 把「产物路径 + 验收结果 + 一句结论」作为最终回复返回（父会话收到即结束），**不要发消息**。
4. 停止，不主动接下一个单元
