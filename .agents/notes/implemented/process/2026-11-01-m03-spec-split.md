# Agent Note: M0.3 规格按任务拆分

Status: implemented — 五篇任务规格落在 `docs/milestones/M0.3/`，合并规格已删除，链接、预算与索引同批更新。

## Problem

M0.3 任务表有 5 个任务，但实施规格只有一篇合并篇 `M0.3 实施规格`：单篇 16 KB 预算内同时装规则表、计分、抢杠承包、中马与收口，5 个任务的判据、落点、手算分例与实施记录挤在同一篇里。M0.1/M0.2 每任务一篇（各 10 KB），派工按任务、验收按任务、实施记录按任务留位；M0.3 的合并形态没有可独立评审的产物边界，实施记录也没有唯一归属的落点。

## Decision

M0.3 按任务拆五篇：`docs/milestones/M0.3/T-1-规则表与数值定稿.md`、`T-2-庄家计分.md`、`T-3-抢杠与承包.md`、`T-4-中马.md`、`T-5-回归与收口.md`，与 M0.1/M0.2 同形：头部四行（状态 / 依赖 / 对应 master / 验收）、正文按触达面分节、结尾 `## 实施记录` 留位。合并规格 §T-1..§T-5 逐节迁入对应篇，迁入对照逐条核对无遗漏后才删除旧文件；规则总表、`content/rules.json` 锁定块、位值与载荷总表、金标与变异登记随语义归位。登记与链接同批：`tools/doc-gate/doc-budgets.json` 与 `doc-budgets-baseline.txt` 各登五篇 10240、移除旧条目；M0.3 master 任务表、`docs/milestones/README.md` 形态声明、DESIGN 与 specs 的旧链接改指新篇对应节。

## Alternatives considered

- 保留合并规格再建薄索引：同一事实留两份，规则表与位值表在索引和正文各存一版，评审时无法判断哪份权威；索引还占 4 KB 预算却不承载判据。
- 就地扩写合并规格：16 KB 预算已接近上限，五个任务的判据与手算分例叠进去必然超限，只能靠删内容换绿灯，违反「不删必填内容换绿灯」。
- 只拆文件、不同批改登记与链接：链接指向已删文件、预算未登记直接让 G1/G7 变红，等于制造返工。
- 顺带把 M0.4/M0.5 也拆：这两个阶段的规格还没评审，拆开没有内容可填；等实施粒度真有需要时再按本 Note 的形态拆。

## Consequences

- 链接：DESIGN、`specs/protocol.md`、`specs/replay-format.md`、M0.3 master 与里程碑索引改指 `M0.3/T-<n>-*.md` 的对应节；收口条件是全仓对合并规格篇名零引用，五篇正文内部的依据锚由归一化单元统一到篇内节。
- 预算：五篇各 10240，registry 与 baseline 两处同批登记，旧的 16384 条目移除；G8 要求 registry 每个路径都在 baseline 且不高于其值，漏登 baseline 会直接报 ERROR。
- 形态：M0.1–M0.3 按任务拆、M0.4–M0.5 仍用合并实施规格；后续里程碑需要实施粒度时照此拆，先核对迁入对照再删旧文件。
- 评审与派工：每篇可独立派工与评审，跨篇口径冻结在批次决策文件，跨篇矛盾以编号登记，不在单篇里就地改语义。
