## 1. AOT 冒烟

Windows AOT 已有实测先例（见 [godot-aot](../../reference/godot-aot.md)）；本任务验证**本机**可复现。工具：`tools/aot-smoke/aot-smoke.ps1`。Godot 可执行文件（本机）：

````
D:\Program Files\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe
````

步骤：

0. 前置自检：`dotnet --list-sdks` 含 10.0.401；按注册表 `HKLM\SOFTWARE\Microsoft\Windows Kits\Installed Roots` 的 `KitsRoot10` 定位 Windows SDK 并记录实际路径（本机 `E:\Windows Kits\10`），用 `vswhere` 检查 MSVC C++ 组件；Godot 4.7.2 mono 与导出模板存在。缺任一 → 停，不伪造 AOT 通过。
1. 清空 `<repo>/build/windows/`。
2. 导出：`Godot...console.exe --headless --path <repo>/src/Mahjong.Client --export-release "Windows Desktop" <repo>/build/windows/Mahjong.exe`；`<repo>` 为仓库根绝对路径，Godot CLI 的相对路径基准不可靠，路径一律写绝对路径。
3. 复制 `<repo>/content/` 到 `<repo>/build/windows/content/`（AOT 冒烟需要内容与查表；必须包含 `rules.json`）。
4. 断言导出数据目录 `data_Mahjong_windows_x86_64/` 无 `coreclr.dll`、`hostfxr.dll`、`GodotSharp.dll`（AOT 原生镜像）。
5. 运行 `<repo>/build/windows/Mahjong.exe --smoke`，60s 超时。
6. 期望 stdout 含 `CONTENT OK <contentHash>` 与 `M0.1 SMOKE OK`，退出码 0，stderr 为空。
7. 失败时打印导出日志与 stderr，退出 1。

AOT 前置自检结果（SDK 实际路径、`vswhere` 输出）记入 T-1 实施记录留证，T-6 复核。

`Startup.cs` 的 `--smoke` 分支必须：加载 `ContentCatalog` + `TableCatalog`（打印表条目数）、打印 contentHash、等待 30 帧后退出。普通启动不加载或只加载内容。

参考：[godot-aot](../../reference/godot-aot.md)。

AOT 冒烟证据：导出 `build/windows/Mahjong.exe` + `build/windows/data_Mahjong.Client_windows_x86_64/` + `build/windows/content/`；数据目录无三个托管运行库 dll；脚本对导出目录中除 `content/` 外的全部文件逐字节扫描 `_mcp_game_helper`，零命中（扫描文件数与字节数以当次脚本输出为准，PDB 大小随构建变化）；3 次 stdout 的 `CONTENT OK 1fc2b54616c4b1e722f794b7e4a4bcb9b5cd3dc6891431a83777da071e2b27cc` 与 `content/manifest.json` 的 `contentHash` 一致。

偏差（裁定与理由）：

1. 数据目录名按 `project.godot` 的 `dotnet/project/assembly_name` 生成，本机为 `data_Mahjong.Client_windows_x86_64/`；§1 步骤 4 与 [godot-aot](../../reference/godot-aot.md) 原先写的 `data_Mahjong_windows_x86_64/` 不成立，脚本改用 `data_*_windows_x86_64` glob 并打印实际名，cookbook 与 reference 同批改正。
2. 本机 Godot 4.7.2 导出版启动时固定向 stderr 写两行引擎证书库错误（`ERROR: Failed to read the root certificate store.` 与其 `at: get_system_ca_certificates (...)` 行），与本仓内容与 AOT 无关；§1 步骤 6 的「stderr 为空」收窄为「stderr 整段大小写敏感精确匹配这两行（恰好两行、固定顺序），其它任何字节判失败」，理由见 [Note](../../../.agents/notes/implemented/process/2026-10-29-aot-smoke-tool.md) 的 rejected 项。
3. `Mahjong.Client.csproj` 增加 `WarningsNotAsErrors=IL2104;IL3053`：publish 的 ILC 阶段对 GodotSharp 必然聚合这两条告警，全局 `TreatWarningsAsErrors` 会升级成 MSB3077 让导出失败；只把这两条第三方告警降级为非致命，其它告警仍是错误。
4. `project.godot` 增加 `dotnet/project/solution_directory="../../"`：Godot .NET 导出按该目录扫描 `*.sln` 并用 csproj 绝对路径匹配，根 `Mahjong.sln` 被选中，不新增项目级 sln。
5. `export_presets.cfg` 的 `exclude_filter="addons/godot_ai/*"`：MCP 插件不入导出包，产物扫描才能零命中。
6. 冒烟进程传 `--log-file build/aot-smoke-run.log`：避免与在跑的编辑器争用 `user://logs/godot.log` 而在 stderr 引入日志轮转错误。
