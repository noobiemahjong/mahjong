# Agent Note: 变异台账改为用户批次统一执行

Status: implemented — 常规任务只登记条目，变异矩阵改由用户安排的批次统一执行；登记处 `docs/reference/mutation-ledger.md`。

## Problem

对抗审核的变异矩阵（单任务几十个单点变异）需要隔离副本、逐条注入、重建、跑全量测试再恢复，一轮实耗 15 分钟以上；它夹在 agent 开发循环里，占用的是任务收口时间，而结论只有「测试判别力够不够」一条。变异日志与结果落在 gitignore 的 `.reviews/`、`build/`，不进仓库；每个任务各跑一遍，仓库事实没有增加。常规任务已有 L1–L3 与对抗审核的独立重算/探针，缺的是统一执行节奏，不是每任务都跑。

## Decision

变异台账的唯一登记处是 [docs/reference/mutation-ledger.md](../../../../docs/reference/mutation-ledger.md)：条目字段、编号（`ML-<n>` 连续只增）、结果取值与回填口径都在该文件。

常规任务（含对抗审核）只登记待跑条目：不重建变异副本、不跑变异矩阵，汇报按红线写「已登记、未跑」。执行只在用户安排的批次进行：整批跑完把 `KILLED` / `SURVIVED` / `BUILD_FAIL` 回填台账，`SURVIVED` 附等价性论证或弱断言处置。

纪律进根 [AGENTS.md](../../../../AGENTS.md) 常驻规矩；流程进 [docs/development.md](../../../../docs/development.md)；reference tier 登记该文件（[docs/AGENTS.md](../../../../docs/AGENTS.md)）；新文档与本文同批登记 `doc-budgets.json` 与 baseline（8192B）。

## Alternatives considered

- **每任务只跑高风险变异（仲裁、原子性）**：仍要重建隔离副本与跑全量基线，固定成本不降；「高风险」由审核者主观判定，跨任务不可比。
- **只跑测试侧变异**：判别力关注生产回归，测试侧变异测的是 oracle 独立性；T-1b 审核已证明该维度可单独判等价（字面金标仍在），不能替代生产侧。
- **交给 CI 定时跑**：仓库没有变异脚本与隔离副本工具链，跨平台构建成本高；执行时机也由 CI 决定，与「用户安排时间」相悖。
- **台账分散进各任务文档**：批量执行要逐篇收集条目，跨任务编号会重号；任务文档承载判据与实施记录，不是待跑队列。
- **保留每任务跑但减少变异数**：覆盖率随任务缩小而不可比，台账也失去「整批可复现」的意义。

## Consequences

- 常规任务不产出新的判别力证据：任务文档与汇报必须写「台账已登记、未跑」，不得把未跑写成绿灯。
- 批量执行在隔离副本上做，基线（变异前全绿与恢复后全绿）与逐条结果留在 gitignore 的 `.reviews/`、`build/`；台账只存条目与结果。
- 条目不因未跑删除，编号只增；重跑不改编号，只覆盖结果列。
- 台账条目由任务登记、用户批次执行后回填；登记任务文档保持判据与实施记录，不复制台账内容。
