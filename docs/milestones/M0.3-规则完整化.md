## 4. 验收

- 全部规则变体逐条有单测与手算分例；抢杠/承包优先级明确。
- 8 局全 Bot 含全部变体可完成；同 seed 两次 StateHash 一致。
- 新事件/同步值写入流，M1 回放能覆盖；`content/rules.json` 变体配置加载失败有可读错误。
- M0.2 测试按新 payload/规则显式更新后全绿；旧金标不被静默改写。
- AOT 冒烟通过；doc-gate/CI 绿。

## 5. 完成定义

1. 规则表经逐条评审定稿，代码、配置与表一致。
2. 全部规则变体单测/金标全过；8 局全 Bot 确定性一致。
3. `content/rules.json` 变体配置生效，contentHash 更新并记录。
4. AOT 冒烟、doc-gate/CI 绿；文档与结果齐。
5. 范围守门：无点炮/荣和，无网络/美术。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 规则语义与本地玩法不一致 | T-1 逐条评审；规则表与代码同批评审 |
| 抢杠引入点炮式响应，破坏“无点炮”边界 | 只允许补杠牌抢杠；响应窗口独立于弃牌窗口 |
| 承包叠加导致重复计分 | 一次胡牌只取一个承包者，优先级写死并测例覆盖 |
| 新规则改变 contentHash/金标 | M0.3 内重录金标，M1 不复用 M0.2 旧回放 |
