## 1 翻马流程

中马是 [T-2 §4](T-2-庄家计分.md#4-结算顺序与事件) 五步结算的第 4 步；顺序唯一家是 T-2，本节只写中马步。时机 = 胡牌金额记完、`Release` 取样之前；流局不翻马。

- 取牌与落区：`GameState.Wall` 头端取一张（同 `GameState.DrawFromWall` 头端，杠补取尾不参与，墙数 −1），追加到新增 `GameState.Revealed` 公共揭示区，区域 id = `ZoneId(ZoneId.PublicSeat, ZoneKind.Revealed)`；`ZoneKind.Revealed` 有枚举值 4，缺的是区域实例。依据：符号 `GameState.Wall`、`GameState.DrawFromWall`、`ZoneKind.Revealed`、[DESIGN §4.1](../../DESIGN.md#41-牌与区域)。
- 墙空跳过：取牌前 `Wall.Count == 0` 即整步跳过，无事件、无支付、无区域变化，其余结算照常。依据：[T-2 §4](T-2-庄家计分.md#4-结算顺序与事件)。
- 哈希：`StateHash` 布局追加 `Revealed` 段 ⇒ `LayoutVersion` 2→3，`Measure`/`Write` 同步，两条 hash 与字节长同批重录并落 [T-5 §2](T-5-回归与收口.md#2-金标重录)。依据：[StateHash 布局 Note](../../../.agents/notes/implemented/architecture/2026-10-29-state-hash-byte-layout.md)。

## 2 映射与计分

- 映射：`horseSeat = tile.Id % 4`；`tile.Id` 是物理牌 1–136，`%4` 落到座 0–3 恰好四座各 34 次；不用 `Type.Id`（0–33）。依据：[T-1 §1](T-1-规则表与数值定稿.md#1-规则总表) RB-06。
- 位值与掩码：`HorseWinner = 512`，单一位规则，赢家笔与三家 payer 笔同置、聚合取并集；`ScoreManager.AllActionTypes` 并入该位，`KongActions` 不变，未进掩码时 `Apply` 抛 `ArgumentOutOfRangeException`。依据：符号 `ScoreManager.AllActionTypes`、`ScoreManager.Apply`；位值总表见 [T-1 §4](T-1-规则表与数值定稿.md#4-事件协议回放字段总表)。
- 金额：`horseSeat == winSeat` 且 `horseBonus > 0` → 赢家 +3×`horseBonus`、其余三家各 −`horseBonus`；不中即无支付、不置位、不动暂存。依据：[T-1 §2](T-1-规则表与数值定稿.md#2-支付与叠加口径)。
- 关闭：`horseBonus = 0`（`variants` 缺省同值）⇒ 不翻马、无事件、无支付。依据：[T-1 §3](T-1-规则表与数值定稿.md#3-contentrulesjson-schema)。
- 独立性：payer 恒为三家，与承包者无关；庄家可同时是跟庄 payer 与马 payer。依据：[T-1 §1](T-1-规则表与数值定稿.md#1-规则总表) 承包优先级行、[T-1 §5](T-1-规则表与数值定稿.md#5-规则变体交互矩阵)。
- 边界：流局不翻马；第 8 局照常；抢杠胡、杠上开花胡照常翻马。依据：[T-2 §4](T-2-庄家计分.md)。

## 3 事件与载荷

- 枚举：`SessionEventKind.HorseRevealed = 13`，紧随 `SeatStateChanged = 12`。依据：[T-1 §4](T-1-规则表与数值定稿.md#4-事件协议回放字段总表)、符号 `SessionEventKind`。
- 载荷 3B，整型小端、字段紧排、无对齐填充：

```text
HorseRevealed = horseSeat u8, tileId u16      (3B)
```

- 同批改 4 处：`HorseRevealedPayload`、`SessionEventBuffer` 的 `EmitHorseRevealed` 与编码/分派、`SessionEventPayloadReader.ReadHorseRevealed`（精确 3B 校验）、`EventPayloadGoldenTests` 逐字节金标。依据：[T-1 §4](T-1-规则表与数值定稿.md#4-事件协议回放字段总表)、[protocol §3](../../specs/protocol.md)。
- 顺序：紧邻 `RoundEnded` 之前、同 tick；`RoundEnded` 之后同 tick 可产 `GameEnded`。依据：[T-2 §4](T-2-庄家计分.md)。
- 可见性：公开事件，四座与观战者同一载荷，`tileId` 直出 1–136，不按 viewer 掩码置 −1（与 `Drew` 不同）。依据：[DESIGN §4.2](../../DESIGN.md#42-可见性)。
- 协议/回放：本地 `13` ↔ 协议与回放 `eventType = 0x1A`，两域映射唯一家是 [T-1 §4](T-1-规则表与数值定稿.md#4-事件协议回放字段总表)，本地 `Deal=3`/`HandSync=4` 无对应 eventType。依据：[replay-format §3](../../specs/replay-format.md)。
- 客户端消费：`LocalGame._Process` 的 `switch` 覆盖 7 个 `SessionEventKind`（`RoundStarted`/`TurnStarted`/`Discarded`/`Meld`/`Drew`/`RoundEnded`/`GameEnded`），其余走默认分支被忽略，`HorseRevealed` 即其一；最小展示改动 = 该 `switch` 增分支、用 `ReadHorseRevealed` 取 `horseSeat`/`tileId` 显示马牌，并在 `LocalGame.ActionName` 追加 `HorseWinner` 文案（口径见 [T-2 §4](T-2-庄家计分.md#4-结算顺序与事件)）。依据：符号 `LocalGame._Process`、`LocalGame.ActionName`。

## 4 确定性与回放

- 选牌权威端唯一：马牌由 `GameSession` 从墙头取出并写入 `HorseRevealed`；客户端与回放只读事件，不重算、不依赖种子。依据：[DESIGN §5.4](../../DESIGN.md#54-随机与确定性)。
- 同 seed 两次一致：同内容同会话重跑得到相同 `HorseRevealed` 序列、相同 `RoundEnded.scoreDelta`、相同终态 `StateHash`。依据：符号 `DeterminismTests`、`BotPolicyDeterminismTests`、`FlowDeterminismTests`、[DESIGN §5.4](../../DESIGN.md)。
- 回放重建：`HorseRevealed` 按 `0x1A` 入回放流，回放侧按事件序重建 `horseSeat` 与公共揭示区，不解析种子、不重跑规则；墙空路径不产事件、不改哈希，重复结算得同一 `StateHash`。依据：[T-1 §4](T-1-规则表与数值定稿.md#4-事件协议回放字段总表)、[replay-format §5](../../specs/replay-format.md#5-播放规则)。
- SyncValue 例外：[DESIGN §5.4](../../DESIGN.md#54-随机与确定性) 要求随机结果一律经 `SyncValue` 入流；M0.3 以 `HorseRevealed` 事件承载马牌（等价权威值语义），不改 DESIGN 正文；恢复落点 = M1 流层引入 `SyncValue` 时覆盖马牌或声明事件即权威。
