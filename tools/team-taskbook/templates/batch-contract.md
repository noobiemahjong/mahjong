2. 每个覆盖项/轴给：<该文档规定的必填项清单>。
3. **强度目标**：`<目标文档>` 规定的那一档（L1/L2/L3 验证层、doc-gate 判据、测试与性能门槛）；判据见 [开发工作流](../../../docs/development.md) 的「验证分层」节与 `<目标文档>` 对应节。
4. 空缺显式登记：缺失 / 不可达 / 待核项，全部进空白表，不省略；同一必填项出现 ≥3 条待核 ⇒ 视为取证不足，报 Lead 决定是否加采集单元（不许用大量「待核」冒充完成）。
5. 跨篇一致：与 `<上一交付物>` 及既有结论一致；矛盾记 `CR-<本批标识>-n` 并报 Lead。
6. 登记闭环（集成单元）：<该文档规定的登记落点清单>；待跑变异条目不省略，登记进 [变异台账](../../../docs/reference/mutation-ledger.md)。
7. 对抗审核：每个单元的产出都要被独立审核（不是只审最终产物）；审核不得以上游/他单元产物为可信前提——被引用的事实回源核验，上游错则开上游返工。结论含 PASS/FAIL 与分级 findings。

## 3. 角色与文件所有权

| 角色 / 单元 | 承载（subagent / teammate） | 可写文件（仅此） |
|---|---|---|
| planner（U0） | subagent | `.agent-work/<本批标识>/CONTRACT.md`、`units/*.md`、`plan.json` |
| 采集 | subagent | `.agent-work/<本批标识>/evidence-*` |
| 产出 | subagent | `.agent-work/<本批标识>/out-*` |
| 集成 | <subagent / teammate> | 唯一交付件、`.agent-work/<本批标识>/gen-*.ps1` |
| 审核 | <subagent / teammate> | `.agent-work/<本批标识>/review-*` |

**承载选择**（见同级 [lead-brief.md](lead-brief.md) §3.2-2）：默认全 `subagent`；只有「同一角色横跨多个单元 / 需与 Lead 来回对话 / 需共享任务板跟踪」才用 `teammate`，且判 teammate 必须在本表下写一行理由。全批 teammate ≤2；名额是终身的。

**写作用域**：开工前在共享任务板建任务并登记目录级写作用域；并行任务写作用域不重叠；同时活跃 ≤5、批次 ≤8 个单元（以 `docs/development.md` §团队与委派为准）。

**产物归属**：每个单元自建并只写自己的 `check-*.ps1` 与 `handoff-<单元号>.md`；集成单元只写唯一交付件；契约 §6 的验收脚本与 §8 的交接单由对应单元产出，不另立匿名文件。

**禁止越界写**：别人名下的文件只读；需要补内容 → 发消息并报 Lead，不代改。

## 5. 产物契约

产物组织 = 与 `<上一交付物>` **对等**（按同一组织单位：文档=章节与子节、代码=模块与文件布局、数据=表与字段/配置=键与取值；组织单位随任务类型变）；文本文件 UTF-8（无 BOM）、仅 LF；文档类产物的语言与体例以目标文档规定为准。

引用本仓代码只用符号锚点（类型/方法名）或「文件 §小节」，不写源码行号；不手改 `content/tables/*.bytes`。

文档类产物规范见 [docs/AGENTS.md](../../../docs/AGENTS.md)（tier、预算、门禁 G1–G12）。

## 6. 汇报与验收

- 每单元结束：先写交接单（结论 / 已排除 / 待办 / 风险，见同级 [cell-brief.md](cell-brief.md) §8），再回报——teammate 用 `send_message`，subagent 用最终回复；内容 = 产物路径 + 验收结果 + 一句结论。
- 验收命令：`pwsh -File .agent-work/<本批标识>/check-<x>.ps1`，期望 <输出> 且 exit 0。
- 每个验收脚本至少三条结构性断言：覆盖项数 == 本契约 §2 声明值；锚点缺失数 == 0；编号集合 == 期望集合。
- 审核 FAIL：新开修复单元并读交接单，不回到原会话。
- 验证分层按 [开发工作流](../../../docs/development.md) 的「验证分层」节：改哪个面跑哪个面，汇报只写真正跑过的命令。
- 提交粒度：一任务一 commit（Conventional Commit，标题 ≤50 字），提交前按改动面跑对应门禁；不 push。

## 7. 红线

- 不 push；不改只读基线目录；不悄悄简化（简化须登记）；只写自己名下文件。
- **不手改 `content/tables/*.bytes`**：替换/重生成需 Note + 逐条对比。
- 常规任务不跑变异矩阵：只把待跑条目登记进 [变异台账](../../../docs/reference/mutation-ledger.md)，结果列写「未跑」，汇报写「已登记、未跑」。
- 外部参考仓（含旧 Unity 项目）只读，不改不写（见根 `AGENTS.md` 红线）。
- MCP 写操作（场景/资产/导入）必须属于已确认任务；工具不得隐式触发。
- 不伪造绿灯：没跑写「未跑」；门禁证据附命令与退出码。
